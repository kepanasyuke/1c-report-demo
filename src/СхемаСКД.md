# Сборка схемы компоновки данных

Ориентир по времени: 10 минут в Конфигураторе. Всё, что ниже, — это ровно те
настройки, которые на собеседовании обычно просят показать «руками».

## 1. Каркас

1. `Файл → Новый → Внешний отчёт`, имя `ВедомостьПоТоварамНаСкладах`.
2. `Открыть схему компоновки данных` → `Готово` (согласиться на создание).
3. Переименовать схему в `ОсновнаяСхемаКомпоновкиДанных`.
4. Вкладка **Наборы данных** → `Добавить набор данных` → `Запрос`.
5. Кнопка `Запрос` → вставить текст из `src/Запрос.txt` (без строк-комментариев
   сверху, только сам запрос) → `ОК`.

## 2. Поля и ресурсы

Вкладка **Ресурсы** — добавить четыре поля и задать выражения:

| Ресурс             | Выражение           |
|--------------------|---------------------|
| НачальныйОстаток   | `Сумма(НачальныйОстаток)` |
| Приход             | `Сумма(Приход)`     |
| Расход             | `Сумма(Расход)`     |
| КонечныйОстаток    | `Сумма(КонечныйОстаток)` |

Вкладка **Вычисляемые поля** — добавить одно поле:

| Поле      | Выражение                                                        |
|-----------|------------------------------------------------------------------|
| Контроль  | `НачальныйОстаток + Приход - Расход - КонечныйОстаток`           |

`Контроль` — это встроенная проверка арифметики отчёта: в каждой строке
результата обязано быть `0`. На собеседовании это удобный повод сказать про
контроль сходимости остатков.

## 3. Параметры

Вкладка **Параметры** → `Добавить` два параметра:

| Параметр        | Тип   | Заголовок      |
|-----------------|-------|----------------|
| `НачалоПериода` | Дата  | Начало периода |
| `КонецПериода`  | Дата  | Конец периода  |

Оба параметра должны быть **не** помечены как «Ограничение доступности»
(галочка `Ограничение` снята) — иначе пользователь не сможет их менять.

Если период не заполнен, модуль объекта (`src/МодульОбъекта.bsl`,
`УстановитьПериодПоУмолчанию`) подставит текущий месяц.

## 4. Настройки по умолчанию

Вкладка **Настройки** → `Открыть настройки по умолчанию`:

- **Структура**: группировка `Склад` → вложенная группировка `Номенклатура` →
  вложенная группировка `Характеристика`.
- **Выбранные поля** (порядок важен):
  `Номенклатура`, `Характеристика`, `НачальныйОстаток`, `Приход`, `Расход`,
  `КонечныйОстаток`, `Контроль`.
- **Отбор**: `Склад` `В списке` — пустой список (пользователь заполняет сам).
- **Порядок**: `Номенклатура` по возрастанию.

## 5. Условное оформление (одна минута, но выглядит дорого)

Вкладка **Условное оформление** → `Добавить`:

- Оформление: `Цвет текста` = тёмно-красный, `Цвет фона` = розовый.
- Условие: `КонечныйОстаток` `Меньше` `0`.
- Оформляемые поля: `КонечныйОстаток`.

Второе оформление: `Контроль` `Не равно` `0` → жёлтая заливка на поле
`Контроль` (дыра в арифметике — сигнал разбираться с движениями регистра).

## 6. Модуль и запуск

1. В окне отчёта `Открыть модуль объекта` → вставить `src/МодульОбъекта.bsl`.
2. `Файл → Сохранить как` → `ВедомостьПоТоварамНаСкладах.erf`.
3. `Файл → Открыть` этот `.erf` в рабочей базе → `Сформировать`.

### Если платформа не знает `КомпоновщикНастроек`

Свойство изолировано в одной функции `ТекущиеНастройки()`
(`src/МодульОбъекта.bsl`, область `СлужебныеПроцедурыИФункции`). На сборках,
где оно недоступно в модуле объекта, замените тело функции на:

```bsl
Функция ТекущиеНастройки()

	Возврат НастройкиКомпоновкиДанных;

КонецФункции
```

Больше нигде в коде платформенных «магических» вызовов нет — именно для этого
все обращения к API вынесены в однооператорные функции.
